# Исходники «Просмотр DXF и PDF»

Здесь всё, из чего собирается приложение. Файлы в корне репозитория (`index.html`, `sw.js`, `lib/` …) — результат сборки, их руками не правят.

## Состав

| Файл | Что внутри |
|---|---|
| `head.part` | разметка и CSS (начало HTML до `<script>` с ядром) |
| `help.part` | встроенная справка (кнопка «?», F1) — обновлять вместе с функциями |
| `core.part` | метки для pdf.js и ядро разбора DXF — функция `DXFCORE()` |
| `geom.part` | сравнение геометрии двух DXF (`GEOCORE()`): совмещение — сдвиг, поворот, зеркало — и поиск отличий с допуском; считается в отдельном потоке |
| `main.part` | основной код: окна просмотра `Pane`, сетка, дерево, история, ярлыки, пары, сравнение, второй монитор, PWA |
| `build.py` | сборка (см. ниже) |
| `build_original.py` | сборка в том виде, как она работала во временной папке сессии — для справки, не запускать |
| `vendor/pdfjs-3.11.174/` | библиотека pdf.js (Mozilla, Apache 2.0) |
| `assets/` | иконки приложения |
| `tests/` | автотесты в Chrome (Playwright) и тестовые файлы |

Итоговый HTML = `head.part` + `help.part` + `core.part` + `geom.part` + `main.part`, склеенные подряд, плюс подстановки в метки `<!--@@PWAHEAD@@-->`, `/*@@PDFJS@@*/`, `/*@@PDFWORKER@@*/`.

## Сборка

Нужен только Python 3 (без дополнительных пакетов), Windows/Linux/macOS:

```
python src/build.py
```

Результат в `src/dist/` (в git не попадает):

- `dxf-viewer.html` — один файл, pdf.js внутри; открывается двойным кликом, работает офлайн без установки;
- `pwa/` — приложение для GitHub Pages: `index.html`, `sw.js`, `manifest.webmanifest`, иконки, `lib/pdf*.js`;
- `dxf-viewer.src.html` — склеенный исходник без pdf.js (для проверки).

Версия офлайн-кэша в `sw.js` = хеш `index.html`, поэтому после любой правки у пользователей появляется «Доступна новая версия → Обновить».

## Откуда pdf.js

`vendor/pdfjs-3.11.174/pdf.min.js` и `pdf.worker.min.js` — без изменений из npm-пакета `pdfjs-dist@3.11.174` (`package/build/`). Получить заново:

```
npm pack pdfjs-dist@3.11.174
tar xzf pdfjs-dist-3.11.174.tgz
copy package\build\pdf.min.js, pdf.worker.min.js → src/vendor/pdfjs-3.11.174/
```

При смене версии pdf.js поменять папку в `build.py` (`LIB`) и имя кэша `dxfv-lib-…` в шаблоне `sw.js` там же.

## Выкладка в GitHub Pages

Pages публикует корень ветки `main`. После сборки:

1. скопировать содержимое `src/dist/pwa/` в корень репозитория с заменой (`index.html`, `sw.js`, `manifest.webmanifest`, иконки, `lib/`);
2. закоммитить вместе с изменёнными исходниками в `src/` и отправить (`git push`).

Через 1–2 минуты новая версия на https://mrtekhnik.github.io/dxf-viewer/.

## Тесты

`tests/t*.py` — сценарии в Chrome через Playwright (Python), `tests/regress.sh` — прогон всех. Перенесены как есть из рабочей папки сессии, поэтому в них зашиты пути той среды (`/home/claude/dxf-viewer.html`, `/tmp/claude-0/t`, `/usr/bin/google-chrome`); для запуска в другом месте пути нужно поправить. Тестовые данные (`dxf/`, `kit/`, `tree/`, `inv/`, `cmpA/`, `cmpB/` …) — искусственные файлы; часть сделана `gen.py`.

Рабочий DXF пользователя для теста `t20.py` (выноски с испорченной кодировкой) в репозиторий намеренно не положен — репозиторий публичный; без него `t20.py` не пройдёт.
